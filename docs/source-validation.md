# 코드 분석 검증 기준점 (2026-11-03)

Int/Bool・조건식・비교/단락 논리・abs/div/mod・자기/상호 재귀를 코드 입력에서 지원한다. 모든 정의에 구체 시그니처를 요구한다. 원본 hs_complex_tests 01–06 및 각 변형 두 개, 총 18개의 Graph JS 결과와 GHC 9.10.3 결과를 비교했고 모두 일치했다. fixture의 .hs 원문은 변경하지 않았다.

직전 검증: 단위 556/556, 코드 분석 UI 8/8, 패턴 UI 6/6, 빌드 통과. 일반 UI 42/43에서 게임 간 Model 저장 충돌 한 건과 연관 페이지 오류가 남았다. 이 기존 문제는 known-issues.md에 별도로 기록한다. 새 기능의 정상 결과로 합산하거나 검사를 비활성화하지 않는다.

## 실제 브라우저의 4초 종료 경로

`npm run test:source-timeout`은 별도의 임시 Chrome 프로필에서 앱의 실제 sourceRunner와 UI를 사용한다. 계산 Worker만 테스트용 실제 Blob Worker로 대체해 4.8초 후 응답을 예약한다. 별도 MessagePort의 50ms heartbeat로 살아 있는 Worker임을 확인하며, 제품의 setTimeout(4000), terminate 및 상태 정리 경로는 교체하지 않는다. 제품 평가기의 깊이/횟수/시간 제한을 약화하지 않는다.

실행 기록: 약 4010ms에서 시간 초과 메시지, terminate 1회, 그 전 heartbeat 80회, UI interval 105회. Worker 종료 후 heartbeat가 멈췄고 예약된 결과가 오지 않았다. 정상 코드를 다시 변환/평가해 42를 얻었고 재생 중단은 그 결과를 유지했다. 종료된 Worker에 늦은 메시지 이벤트를 별도로 전달하는 보충 검사도 새 결과를 덮어쓰지 않았다. UI details 조작도 계산 대기 중 동작했다. 콘솔/페이지 오류 없음.

이 결과는 **통제된 실제 Worker를 이용한 타이머/종료 제어 경로 검증**이다. 실제 평가기에 장시간 부하를 줘 4초를 소진한 검증은 아니다. 보통 평가기의 1.5초/깊이/계산량 보호가 먼저 작동한다. 계산 중단(Worker 종료)과 재생 중단(이미 계산한 기록만 중단)은 별도 동작이다.

## 실행 기록 탐색 회귀

일반 UI의 이전 두 실행은 서로 다른 시나리오에서 응답 대기를 멈추지 못했다. 두 번째 실행이 멈췄을 때 별도 Chrome 디버깅 연결에서 같은 페이지가 응답했다. 명령을 기록한 비교 실행에서는 일반 UI 43개가 한 번에 끝났고, 기존 클릭 카운터 전환의 Model 저장 충돌로 1개 시나리오와 그 페이지 오류가 남았다.

검사가 겹친 실행에서는 새로고침 후 앱 초기화가 끝나기 전에 기존 고정 대기가 끝나는 경우도 재현했다. 테스트는 이제 새 문서의 편집기가 준비됐는지 확인하고, 일반 UI 실행기는 응답 없는 브라우저 명령의 이름과 ID를 남긴다. 일반 편집 경로는 코드 평가 Worker와 기록 재생을 시작하지 않는다. 코드 분석 UI 검사는 재실행, 계산 중단, 재생 중단, 탭 전환 후 결과와 기록이 섞이지 않는지도 확인한다.
