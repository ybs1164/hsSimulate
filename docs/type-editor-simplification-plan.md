# 타입 사용·편집과 패턴 매칭 단순화 계획

이 문서를 기준으로 타입 사용·편집 화면과 함수 내부 패턴 매칭을 구현했다. 분기는 패턴 메타데이터와 전용 본문 그래프로 저장하고, 기존 원시 분기·람다 평가 경로를 함께 사용한다. 아래는 개편의 설계와 완료 기준이다.

목표는 타입을 함수와 같은 조작으로 사용하고, 타입 편집 화면에는 그 타입의 구조를 보여 주며, 분기는 함수 본문에서 직접 작성하는 것이다.

1. **타입 항목에서 바로 생성자를 사용한다.**

   현재 `Types`의 타입 항목은 편집기만 열고, 생성자 호출은 그 아래 유도 함수 목록에서 따로 추가한다. 생성자는 이미 일반 함수와 같은 커링·부분 적용 구조를 사용한다(`src/typeDecls.js`의 `derivedDefinitions`).

   - 생성자가 하나인 타입은 타입 항목의 추가 버튼·드래그로 그 생성자 호출을 만든다. 타입 이름과 생성자 이름이 달라도 실제 생성자에 연결한다.
   - 생성자가 여러 개인 타입은 추가할 때 생성자를 고른다. 사용자가 선택하기 전 첫 생성자를 임의로 적용하지 않는다.
   - 타입 편집은 별도 편집 버튼과 더블클릭으로 연다. 함수 목록과 추가·편집 조작을 맞춘다.
   - 필드가 없는 생성자는 값으로, 필드가 있는 생성자는 입력 슬롯이 있는 호출로 표시한다. 비어 있는 슬롯은 기존처럼 부분 적용과 고차 함수 전달에 사용할 수 있다.
   - 호출은 기존 생성자 id를 참조한다. 생성자 커스터마이즈와 타입 편집에 따른 호출 이전도 그대로 따른다.
   - 타입을 넣는 자리에서는 기존 타입 생성자 적용을 유지한다. 예를 들어 `Tree a`는 `Tree`의 타입 인자 슬롯에 `a`를 넣는 모양이다. 값 캔버스에서는 `Leaf`·`Node`를 호출한다.

2. **타입의 구조에 맞춰 편집 화면을 줄인다.**

   현재 `renderTypeEditor`는 타입·매개변수·생성자·유도 연산을 별도 카드와 간선으로 펼친다. 기본 화면은 타입 이름과 매개변수 아래에 생성자와 필드를 담는 하나의 편집 영역으로 바꾼다.

   | 타입 구조 | 기본 화면 |
   | --- | --- |
   | 생성자 하나: `Model` | 이름 아래 필드 목록. 같은 이름의 타입·생성자 머리글은 합쳐 표시 |
   | 필드 없는 생성자 여럿: `Direction` | `North`, `South` 등의 선택지 목록 |
   | 필드가 있는 생성자 여럿: `Tree a` | `Leaf`, `Node`별 접을 수 있는 영역과 각 필드 |
   | 재귀 필드 | 필드 타입에 `Tree a`를 표시. 필요할 때 펼쳐 확인 |

   - 기본 노출: 타입 이름, 타입 매개변수, 생성자 이름, 필드 이름·타입, 추가·삭제, 편집 오류.
   - 기본 화면에서 생략: `ι`·`π`, kind 설명, 중복 생성자 시그니처, 자동 적용 성공 문구, 매개변수 연결선, 유도 연산 카드.
   - `data`/`newtype`, deriving 전략, 인스턴스, 유도 함수 커스터마이즈, 선언 코드와 구조 그래프는 상세 영역에서 접근한다.
   - 필드 읽기·갱신은 필드 행에서 필요할 때 추가한다. 사이드바에 모든 `get`·`set`·`over`를 펼쳐 놓지 않는다.
   - `foldTree` 같은 재귀자는 상세 함수 목록에서 유지한다. 패턴 매칭은 재귀 결과를 자동으로 계산하는 fold와 구별한다.
   - 생성자 순서 변경은 명시적인 이동 조작으로 한다. 화면에서 카드를 옮긴 것만으로 `Ord`와 생성자 순서가 바뀌지 않게 한다.
   - 한 필드 타입이라고 자동으로 `newtype`으로 바꾸지 않는다. 기존 선언의 평가·인스턴스 의미를 보존한다.

3. **record는 필드 작성에 따라 자동 적용한다.**

   `draftToSource`는 이미 모든 필드에 이름이 있으면 record 문법을 만든다. 이 규칙을 사용하고 `{ record }` 전환 버튼은 제거한다.

   - 필드 추가, 타입 드롭으로 생성자 추가 등 모든 작성 경로에서 필드 이름을 자동 부여한다. 이름은 바로 바꿀 수 있다.
   - 자동 이름은 생성자 안에서만 검사하지 않고, 생성될 사영 함수와 기존 함수의 이름 충돌까지 피한다. 기존 선언 검사기를 최종 검증에 사용한다.
   - 필드 없는 생성자는 그대로 둔다. 여러 생성자에 필드 이름이 있어도 해당 생성자에만 존재하는 필드의 전역 접근 함수를 자동 생성하지 않는다. 현재처럼 단일 생성자 record에만 전체 타입에서 안전한 사영·갱신 함수를 제공한다.
   - 기존 위치 기반 선언은 불러오기·열기만으로 바꾸지 않는다. 편집으로 필드를 추가하거나 이름을 지정할 때 필요한 이름을 한 번에 채워 record로 전환하고, 실행 취소 한 번으로 되돌릴 수 있게 한다.
   - 이름·순서 변경은 기존 안정 키와 `migrateTypeEdit`를 사용해 연결을 보존한다. 생성자 인자 순서와 런타임 값 구조는 유지한다.
   - record 전환 후 `Show`의 출력이 달라질 수 있으므로 값 출력·파싱도 검증한다. 기존 위치 기반 값 입력은 계속 허용한다.

4. **함수 본문에 패턴 매칭 블록을 추가한다.**

   매개변수나 중간 계산값에서 `패턴 매칭`을 선택하면 대상 타입에 맞는 분기를 만든다. `caseTree` 호출과 분기별 람다를 사용자가 직접 조립하는 과정은 생략한다.

   ```haskell
   size tree = case tree of
     Leaf -> 0
     Node left value right -> 1 + size left + size right
   ```

   - 블록은 대상 입력 하나, 생성자별 패턴과 본문, 공통 결과 출력 하나로 보인다. 생성자와 필드 이름은 실제 선언에서 가져온다.
   - 분기 안에서는 패턴으로 꺼낸 필드가 지역 변수로 보인다. 바깥 함수의 매개변수와 값도 사용할 수 있다. 분기 변수는 다른 분기나 바깥으로 연결할 수 없다.
   - 각 분기 본문은 같은 함수 편집 맥락에서 펼치거나 접는다. 별도의 이름 있는 함수를 만들 필요가 없다.
   - 중간값과 중첩 분기도 같은 블록을 사용한다. 입력 매개변수 전용 기능으로 제한하지 않는다.
   - 한 생성자 record도 같은 방식으로 분해할 수 있다. `Model`을 매칭하면 필드들을 지역 변수로 사용할 수 있다.
   - 첫 범위는 사용자 ADT의 생성자 패턴과 변수·`_`이다. 최상위 기본 분기도 지원한다. 리터럴·가드·한 패턴 안의 중첩 패턴은 후속 범위로 둔다. 중첩 매칭 블록으로 필요한 분해는 가능하다.
   - 누락된 생성자와 비어 있는 분기 본문을 구별해서 표시한다. 기본 분기가 없으면 생성자를 모두 처리해야 실행할 수 있다. 중복·도달 불가능한 분기도 표시한다.
   - 분기 결과는 같은 타입으로 추론한다. 대상 타입의 매개변수는 분기 필드 타입에도 함께 적용한다.
   - 실행에서는 선택된 분기만 계산하고, 사용하지 않는 필드를 강제하지 않는다. 재귀도 기존 함수 호출 규칙을 따른다.

5. **저장 표현과 실행 변환을 나눈다.**

   편집·저장은 대상 값, 패턴, 분기 본문을 가진 구조화된 `match`로 한다. 타입 검사와 실행에 앞서 공통 변환 단계에서 기존 생성자 분기 원시 연산과 람다 그래프로 변환한다. 분기 캡처는 기존 람다 리프팅 방식을 사용한다.

   - 새 매칭은 생성자의 실제 구조를 검사한다. 사용자가 재정의한 `caseTree` 함수 본문을 새 패턴 매칭의 의미로 사용하지 않는다.
   - 변환된 내부 함수는 사용자 함수 목록·프로젝트 원본에 중복 저장하지 않는다. 편집 표현을 원본으로 유지한다.
   - 변환 과정에서 원본 블록·분기·변수 위치를 기록해 타입 오류와 실행 오류를 해당 위치에 표시한다.
   - 코드 출력은 내부 변환 결과 대신 `case … of`로 보여 준다. 토큰에서 원본 그래프 위치로 이동하는 기능도 유지한다.
   - 편집기 실행, 노드 실행, 연습 채점, 법칙 검사, HTML 내보내기가 같은 변환 결과를 사용하게 한다. 내보낸 게임에도 필요한 내부 정의가 포함되어야 한다.
   - Bool·리스트 등 특수 런타임 표현을 가진 Prelude 타입은 대응 분해 연산을 확인한 뒤 같은 UI에 연결한다. 사용자 ADT용 구현을 표현 확인 없이 그대로 적용하지 않는다.

6. **기존 프로젝트와 타입 편집을 이어 준다.**

   - `caseTree`를 포함한 `caseT`는 기본 라이브러리·타입 편집 화면에서 생략한다. 기존 호출과 부분 적용·고차 함수 사용은 호환 정의로 계속 실행한다.
   - 기존 `caseT` 호출을 자동으로 삭제하거나 재작성하지 않는다. 원래 호출 노드에는 동작을 보존하는 `패턴 매칭으로 변환`을 제공한다. 커스텀 분기 함수는 원시 분기와 같다고 가정해 변환하지 않는다.
   - 매칭 패턴은 생성자·필드의 안정 키를 참조한다. 현재 편집 중에만 유지하는 키를 저장 후에도 유지하도록 확장하고, 구버전에는 불러올 때 부여한다.
   - 생성자·필드 이름 변경과 재정렬은 기존 분기와 변수 연결을 보존한다. 생성자 추가 시 기본 분기가 있으면 그 분기가 처리하고, 없으면 미완성 분기를 표시한다.
   - 생성자·필드 삭제로 참조가 깨지면 해당 위치에 오류를 남긴다. 다른 생성자·필드에 조용히 연결하지 않는다.
   - 저장 버전을 올리고 구버전 가져오기, 저장·재열기, 실행 취소·다시 실행, 기존 선언 그래프 배치 보존을 확인한다.

7. **구현 순서와 완료 기준**

   1. 타입 항목의 생성자 추가 조작과 간결한 타입 편집 화면을 구현한다. record 자동 이름 부여와 기존 타입 편집 이전을 함께 정리한다.
   2. 안정 키 저장, 매칭 표현, 범위 검사, 공통 그래프 변환을 구현한다. 생성자별 타입 적용·결과 타입 통일·지연 평가를 검증한다.
   3. 함수 본문의 매칭 블록과 지역 변수 연결을 구현한다. 코드 출력·오류 위치·저장·채점·내보내기를 연결한다.
   4. `caseT` 기본 노출을 제거하고 기존 호출의 선택적 변환을 추가한다. 대표 템플릿·학습 안내를 새 흐름으로 바꾼다.

   주요 변경 위치는 `src/main.js`, `src/style.css`, `src/declGraph.js`, `src/typeDecls.js`, `src/typeEdits.js`, `src/project.js`, `src/haskellPrint.js`와 타입 검사·실행의 공통 진입점이다. 매칭의 표현·검사·변환은 별도 모듈로 분리한다.

   완료는 다음 사용자 동작으로 확인한다.

   - `Model`에서 즉시 호출을 추가하고 일부 필드만 채워 함수로 전달한다.
   - `Tree a`에서 생성자를 고르고, 별도 `caseTree`·람다 배치 없이 `size`를 만든다.
   - 바깥값 캡처, 중첩 매칭, 필드 미사용 시 지연 평가, 분기 결과 타입 오류, 누락 분기와 변수 범위 오류가 올바르게 동작한다.
   - 필드·생성자 이름과 순서를 바꾼 뒤에도 호출·패턴 연결이 보존되고, 삭제·추가 시 필요한 오류가 보인다.
   - 기존 프로젝트와 새 프로젝트가 저장·재열기 및 HTML 게임 내보내기 후 같은 결과를 낸다.

   핵심 의미와 이전 동작에는 Node 테스트를 추가하고, 대표 작성 흐름은 UI e2e로 검증한다. 최종적으로 `npm test`, `npm run build`, 관련 UI e2e를 실행한다.
