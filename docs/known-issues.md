# v1 검증 경계와 수정 이력

## 게임 간 Model 저장 충돌 수정

이전에는 빈 게임에서 클릭 카운터로 전환하면 공용 저장 슬롯의 진입점·타입 표시 이름이 모두 `main`·`Model`이라 다른 구조의 값을 읽었다. 클릭 카운터의 필드 계산은 이 값에서 필요한 필드를 찾지 못해 TypeError를 냈다.

편집기는 프로젝트 ID와 진입점으로 저장 슬롯을 나누고, 모델과 메시지의 타입·생성자·필드 구성이 일치할 때 복원한다. 템플릿은 각자 고유한 슬롯을 사용한다. 같은 프로젝트 재실행·새로고침은 같은 슬롯을 사용하며, **Reset game**은 현재 슬롯의 초기 상태를 저장한다.

프로젝트 ID가 없는 구버전 자동 저장에서 처음 복원할 때는 기존 단일 슬롯의 모델과 메시지를 현재 타입에 맞춰 검사한 뒤 호환 값만 새 슬롯으로 복사한다. 기존 슬롯은 보존한다. 구버전 슬롯에는 소유 프로젝트가 기록되지 않았으므로, 진입점과 값의 구조까지 같은 과거 프로젝트의 소유권을 판별할 수 있는 정보는 없다. ID가 없는 JSON 파일은 새 프로젝트 ID를 받고, 이후 내보낸 JSON은 그 ID를 유지한다.

## Worker 4초 종료의 검증 범위

브라우저에서 응답을 지연시킨 실제 Worker를 사용해 앱의 4초 타이머와 종료·복구를 확인한다. 실제 평가기가 4초를 소진하는 부하 실험은 미검증이다. 앱의 계산량·깊이·내부 시간 보호는 그대로 적용된다. 자세한 방법은 [코드 분석 검증](source-validation.md)을 참고한다.
